# Releasing ShareLink

> **Minimum-OS gate (decided 2026-10-06):** ShareLink keeps iOS/iPadOS 17.0 as its minimum, but the File Provider path cannot be verified on the iPadOS 17.x simulator (see "Known limitation" in `docs/TESTING.md`). The first TestFlight build must be tested on a **physical iOS/iPadOS 17 device** with the on-device Office checklist. If the ShareLink location does not work there, raise `IPHONEOS_DEPLOYMENT_TARGET` (Config/Base.xcconfig and project.yml) before any App Store release.

Archive and upload with Xcode Cloud. `scripts/testflight.sh` is the local alternative.

## First TestFlight build checklist

1. `Config/Local.xcconfig` — copy `Config/Local.xcconfig.example` and set the Team ID.
2. App Store Connect app record.
3. API key in `.env`.
4. `./scripts/testflight.sh --internal-only`
5. Add internal testers.
6. Push the tag and create the GitHub prerelease with the third-party source tarball.

## One-time setup

1. Apple Developer account.
2. `cp Config/Local.xcconfig.example Config/Local.xcconfig` and set the Team ID.
3. In App Store Connect, create the app record: name "ShareLink" (or an available variant), bundle ID `com.ajthom90.sharelink`, SKU `sharelink-ios`. The bundle ID and App Group are registered automatically on the first archive via `-allowProvisioningUpdates`; if not, register them in the developer portal: App ID `com.ajthom90.sharelink` + `.FileProvider`, both with App Groups capability → `group.com.ajthom90.sharelink`.
4. Create an App Store Connect API key (Users and Access → Integrations → Team Keys, App Manager role), save the `.p8` outside the repo, and fill `.env`.
5. In TestFlight, create an internal group and add testers.

## Each build

On a Mac with local signing, `./scripts/testflight.sh --internal-only`, then push the tag and create the GitHub prerelease with the third-party source tarball (the LGPL corresponding-source requirement).

## Xcode Cloud

Xcode Cloud archives ShareLink and uploads it to TestFlight. `ShareLink.xcodeproj` is generated by XcodeGen and git-ignored, so a fresh clone has no project until `ci_scripts/ci_post_clone.sh` runs. That script lives at the repository root (the generated project does not exist at clone time). It installs XcodeGen when it is missing, runs `xcodegen generate`, and writes the git-ignored `Config/Local.xcconfig` on the build machine.

`SHARELINK_DEVELOPMENT_TEAM` is an Xcode Cloud workflow environment variable (mark it Secret). The script writes `DEVELOPMENT_TEAM` from that variable and does not print the value. When the variable is unset, it writes no team line and prints a warning; cloud signing may supply the team. When `CI_BUILD_NUMBER` is set, the script writes `CURRENT_PROJECT_VERSION` from it, so each upload gets a new build number.

Xcode Cloud builds with automatic package resolution disabled. It requires `Package.resolved` at `ShareLink.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved`. The post-clone script copies `Packages/ShareLinkKit/Package.resolved` there. A local `xcodebuild -resolvePackageDependencies` on the generated project produces the same pins (identity, version, and revision): AMSMB2 4.0.3 and GRDB.swift 7.11.1.

The ShareLink scheme in `project.yml` is shared, at `ShareLink.xcodeproj/xcshareddata/xcschemes/ShareLink.xcscheme`. Its Test action includes `ShareLinkUITests`, which needs Docker Samba. The Xcode Cloud workflow uses the Archive action only (iOS, Release). Leave Test off that workflow. The local scheme still includes `ShareLinkUITests`.

### One-time setup

1. Grant Xcode Cloud access to the GitHub repository (install or authorize the Xcode Cloud GitHub app when Xcode asks).
2. In Xcode: Integrate → Create Workflow.
   - Choose this repository.
   - Product: ShareLink.
   - Start condition: branch `main`, or manual.
   - Environment: Xcode 27 and the latest macOS.
   - Environment variable: `SHARELINK_DEVELOPMENT_TEAM` = your Team ID. Mark it Secret.
   - Actions: Archive — iOS. The scheme archives with the Release configuration.
   - Post-actions: TestFlight (Internal Testing).
3. The App Store Connect app record is created during onboarding if it does not already exist.
4. The App Group `group.com.ajthom90.sharelink` must be enabled for both bundle IDs (`com.ajthom90.sharelink` and `com.ajthom90.sharelink.FileProvider`). Cloud-managed signing registers it when it can. Otherwise add the App Group to both identifiers in Certificates, IDs & Profiles.

### After each TestFlight build

Attach the third-party source tarball to a GitHub prerelease. LGPL requires that corresponding source. Build the archive with `scripts/package-third-party-sources.sh`.

## Export compliance

`ITSAppUsesNonExemptEncryption = NO` is set, so no questionnaire.

## Moving to App Store

Privacy policy URL (GitHub Pages `docs/privacy.md` or the raw GitHub URL), support URL (GitHub Issues), screenshots (iPhone 6.9", iPad 13"), App Privacy "Data Not Collected", Standard EULA (see spec §2.1), and price Free.
